**Behaviour change:** TS-TCC's default augmentation no longer collapses the encoder on data that is not zero-mean and unit-scale (for example MINMAX-scaled UCR/UEA series, where the loss sat at chance). `TSTCC` now z-normalizes each series over time before augmentation and in `encode()` (`instance_normalize=True`, also on `TSTCCModelParameters`). The default pair is now per-timestep `TSTCCScaling` (weak) and `Jitter(0.8)` (strong) with segment permutation off (`_default_tstcc_pair(max_segments=..., jitter_sigma=...)` sets both). The original HAR recipe is `augmentation=_default_tstcc_pair(max_segments=8)`. Training also warns once when the loss is still at chance after 500 steps. `_compute_loss` now returns `(loss, batch_size)`, and `tstcc.augmentations` no longer re-exports the shared primitives (import them from `chronocratic.models.augmentation.primitives`).
