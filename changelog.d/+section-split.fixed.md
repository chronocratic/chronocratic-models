**Behavior change:** `TS2Vec`, `CoST` and `AutoTCL` now split each series into `T // max_train_length` sections (NaN-padded at the end) before the random crop, as upstream `fit()` does. Because Lightning owns the loop, this runs per batch, so the sections of a series stay within one batch, and a single long series no longer trains at batch size 1 with a silently zero instance-contrastive loss. There is no split when `max_train_length=None` (the default for `TS2Vec` and `AutoTCL`) or when the series is shorter than `2 * max_train_length`; `CoST` (default 201) changes for series of 402 or more steps. Separately from the split, whenever a batch contains NaN padding, even when no split happens and every series is short, every row is rolled to centre its valid span if padding touches the first or last timestep of any row, and rows that are entirely NaN are dropped, so training on NaN-padded variable-length inputs changes accordingly. CoST batch-filling multiplier of upstream is not ported.
