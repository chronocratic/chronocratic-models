**Behavior change:** `TS2Vec`, `CoST` and `AutoTCL` now split each series into `T // max_train_length` sections (NaN-padded at the end) before the random crop, as upstream `fit()` does. Because Lightning owns the loop, this runs per batch, so the sections of a series stay within one batch, and a single long series no longer trains at batch size 1 with a silently zero instance-contrastive loss. The default `max_train_length` of `TS2Vec` is now 3000 (was `None`), the value the upstream runner uses for every task; `CoST` stays at 201, the value of every upstream script. `AutoTCL` keeps `None` because upstream sets it per dataset (256 to 1024), so pass a value to enable the crop and the split. For `TS2Vec` and `CoST`, series longer than `max_train_length` are therefore cropped by default and those at least twice as long are split; pass `max_train_length=None` to disable both. Separately from the split, whenever a batch contains NaN padding, even when no split happens and every series is short, every row is rolled to center its valid span if padding touches the first or last timestep of any row, and rows that are entirely NaN are dropped, so training on NaN-padded variable-length inputs changes accordingly. CoST batch-filling multiplier of upstream is not ported.
